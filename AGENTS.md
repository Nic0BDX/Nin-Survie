# Travailler sur Nin Survie

Lire TOKEN_MEMORY.md avant de commencer et consulter PROJECT_MEMORY.md seulement pour les systèmes touchés. Travailler dans les fichiers de la mission. Réutiliser les composants et preuves existantes lorsque les fichiers concernés sont identiques.

Sur une mission du studio, livrer un correctif dans l’espace attribué. Le directeur intègre les modifications après contrôle. Toute publication sur la branche stable ou sur le site de production passe par le directeur.

Le rapport tient en six rubriques. Mission, résultat, fichiers, tests réellement exécutés, problèmes, prochaine action. Distinguer un contrôle statique, un test en moteur et une validation sur appareil réel.
